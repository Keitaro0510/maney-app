## D9: 試験版（next.html）で、新しいテーブルのデータを画面にどう渡すか（テーブル分割 #11）

- **データの層だけ差し替える**: テーブルから今と同じ形の `st` を組み立て、各記録に ID を持たせる。画面と計算のコードはほぼそのまま。変えるのは読み込み・保存と、編集の処理（ID で操作を作る）だけ
- **画面と計算も新しい形にする**: `st` をテーブルの形（ID で参照）にして、画面と計算のコードも書き換える。ほぼ全体の書き換えになり、古い版と計算を比べるテストが必須になる

決定: データの層だけ差し替える（2026-10-29）。ただし、これは移行のためだけの「互換層」として、はっきり切り分ける

```
DB のテーブル（正規化・ID が中心）
  ↓ 変換
互換の st（今の画面と計算のためだけ）
  ↓
今の画面・計算
```

理由: 毎日使っているアプリなので、まず安全に移行したい。互換の `st` は仮の設計と割り切る。新しい機能を互換の `st` に積み続けず、DB の側は最終形に近い ID が中心の設計で始める。Phase 4 などで画面と計算を作り直すときに、`st` を経由せず DB のモデル（ドメインモデル）を直接読む形に置き換える。そうすれば今回は安全に移行でき、あとの全面的な作り直しも無駄にならない
