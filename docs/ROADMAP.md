# ROADMAP

毎日使っているアプリなので、**1つの変更 = 1つのブランチ = 1つのPR** で進める（流れは [GIT_WORKFLOW.md](GIT_WORKFLOW.md)）。
各項目の後ろの `ブランチ:` は、名前の例。

## Phase 0: 今の状態の地図を作る

- [ ] `st`（保存しているデータ全体）の構造を図にする（`cards`、`jobs`、`ledger`、`plans`、`shifts`、`fixedCosts` など）
- [ ] 5つのタブ（ホーム・カレンダー・家計簿・シフト・設定）と、主な関数の対応表を作る
- [ ] 動かなくなった機能を洗い出す（楽天カードの明細の取り込みとAIアドバイスは、外部の処理をやめたので止まっている）

## Phase 1: ブランチとPRに慣れる

- [ ] 練習1: 最初のPR（`docs/add-plan`）をレビューしてマージする
- [ ] 練習2: 小さな変更を自分で ブランチ → PR → マージ
- [ ] 練習3: コンフリクトを起こして解決する
- [ ] 練習4: main を保護する（直接の push を禁止）

## Phase 2: 安全網を張る

- [ ] データを JSON でエクスポート・インポートする機能（改修する前の保険）　ブランチ: `feature/export-import`
- [ ] 止まった機能（楽天カードの取り込み・AIアドバイス）の扱いを決めて片付ける（[D5](DECISIONS.md)）　ブランチ: `refactor/remove-card-sync`
- [ ] 計算ロジック（残高の推定、カードの締め日、給与）を関数として切り出し、Vitest でテストを書く　ブランチ: `chore/add-vitest`
- [ ] GitHub Actions で PR ごとにテストを実行する（練習5）
- [ ] sw.js の `CACHE_NAME` を手で上げるのをやめ、デプロイのたびに自動で変わるようにする
- [ ] 今の状態に `v1.0.0` のタグを付ける（練習6）

## Phase 3: タスク管理（最小版）

- [ ] D1〜D3 を決める
- [ ] タスクの追加・完了・削除・期限　ブランチ: `feature/tasks-mvp`
- [ ] ホームに「今日のタスク」と「期限切れのタスク」を表示する
- [ ] カレンダーに期限を表示する
- [ ] 予定の「完了チェック」（今もある）との関係を整理する

**終わりの目安**: 自分が毎日タスクをこのアプリで管理している

## Phase 4: ファイルの分割とTypeScript

- [ ] Vite を入れて、index.html から JavaScript を外に出す（D4）　ブランチ: `refactor/vite`
- [ ] 機能ごとにファイルを分ける（home / calendar / ledger / shift / settings / tasks）
- [ ] 計算ロジックから TypeScript に移す
- [ ] GitHub Actions で Pages へのデプロイもする
- [ ] 長く続くブランチで main の変更を取り込む（練習8）
- [ ] 本番の前に確認できる環境を作る（練習9、D8）

## Phase 5: データを正規化したテーブルに移す

- [ ] 新しいテーブルを設計する（`ledger`、`plans`、`tasks` など）
- [ ] 移行スクリプト（JSONB → テーブル）と、元に戻す手順を用意する
- [ ] しばらくは両方に書き込み、差がないことを確かめてから切り替える
- [ ] 問題が出たら `git revert` で戻す（練習7）

## Phase 6: お金・予定・タスクの連携

- [ ] 予定にひもづく準備のタスク
- [ ] 毎月くり返すタスク
- [ ] 引き落とし前に残高が足りなそうなら、タスクを自動で作る
- [ ] （任意）期限の通知（Web Push、D6）
