# Claude を使って AI の機能を入れる方法（候補。未決定）

**状態: 候補。まだ何も決めていない。** 2026-11-24 の会話で出た案のメモ。進めるかどうか、どの形にするかはユーザーが決める（決めたら `DECISIONS.md` に書く）。

gymapp の文章のフィードバック（gymapp の Issue #8）と、セリフの AI での言い換え（D34 の C）では、「AI を無料で使う道」を探していた。そのとき調べた Gemini の無料枠・ブラウザの LLM・PC のローカル LLM とは別に、**Claude のプランの中で AI を使う道**がある、というのがこのメモの中身。

## 仕組み（案2・案3で共通）

```
Claude のスケジュールタスク（クラウドで、決まった時間に動く）
   │  プロンプト（例:「今週のトレーニングを読んで、振り返りを書いて」）
   ▼
maney-app の MCP（Edge Function `mcp`。docs/MCP.md）── その人として動く（RLS が効く）
   ▼
Supabase（同じプロジェクト）──▶ アプリは、DB に入ったものを表示するだけ
```

- **Claude のスケジュールタスク**: Anthropic のクラウドで動くので、PC を閉じていても動く。2種類ある
  - claude.ai（チャット）のスケジュールタスク: コネクタ（この MCP など）を使える。リポジトリは要らない。案2・案3はこちらで足りる
  - Claude Code のクラウドのスケジュールタスク（旧 Routines）: リポジトリとコネクタを持てる。コードを直す作業向け
- **お金**: 追加の料金はかからない。ただし Claude のプランの使用量に含まれる
- **API キーが要らない**: MCP は OAuth（Supabase Auth）でつながっている。アプリの JS に鍵を置く問題（Gemini の案の課題）が起きない
- **データの行き先**: 記録は Anthropic に送られる。モデルの改善に使われるかは、Claude の設定（プライバシー）で決まるので、進める前に確かめる
- 今ある MCP のツールは、予定・タスク・シフトだけ（D37）。ジムの記録・家計簿・残高は読めない。案ごとに、ツールを足すかを決める必要がある

## 案2: ジムの AI コーチ（文章のフィードバック）

gymapp の #8 に残っている「文章のフィードバック」（例:「ベンチが3週間伸びていません」「脚の記録がありません」）と、gymapp の PLAN の「将来の構想」にある AI コーチを、この仕組みで作る案。

作るもの（たたき台）:
1. MCP に、ジムの記録を読むツールを足す（例: `list_workouts`（期間を指定。種目・重量・回数・RPE・所要時間）、`list_exercises`（部位つき））
2. フィードバックを入れるテーブルと、書くツールを足す（例: `gym_feedback`（週のはじめの日・本文・作った日）と `add_gym_feedback`）。マイグレーションは maney-app の `supabase/migrations/`（D23・D43）
3. gymapp に、最新のフィードバックを出す場所を作る（統計の画面など）
4. スケジュールタスクを作る（例: 毎週日曜の夜。「今週と先週のトレーニングを読んで、伸びた種目・止まっている種目・部位の偏りを、3〜5行で。来週のメニューの提案も」）

決めること:
- #8 のおすすめは「まずルールで作る」だった。ルールで作るか、この案で AI を使うか、両方か（ルールの数字を AI に渡して文章にする、など）
- 出す場所・頻度（週1回か、トレーニングのたびか）
- 同じ仕組みで、マスコットのセリフの言い換え（D34 の C）もできる。ただし、セリフは家計の数字を使うので、家計簿を読むツールが要る。D37 では、家計簿・残高を Claude から読めないようにしたので、そこを変えるかを決める必要がある

## 案3: お金・予定・タスクの連携（ROADMAP の Phase 6）を、スケジュールタスクで動かす

Phase 6 の残りのうち、**今の MCP のツールだけで、すぐ試せるもの**がある。

| Phase 6 の項目 | この仕組みでできるか |
|---|---|
| 予定にひもづく準備のタスク | **今のツールでできる**。例: 毎朝「2週間先までの予定（`list_plans`）を見て、準備が要るもの（旅行・誕生日・提出など）に、準備のタスクを `add_task` で入れて。同じタスクがあれば入れない」。`add_task` は同じタイトル・同じ期限があれば入れない |
| 毎月くり返すタスク | **今のツールでできる**。例: 毎月1日に「家賃の確認」「カードの明細の確認」を `add_task` で入れる。ただし、アプリの機能として作る（くり返しの設定をアプリで持つ）ほうが確実。AI は要らない |
| 引き落とし前に、残高が足りなそうならタスクを作る | **今のツールではできない**（残高を読めない。D37）。この判断は計算だけで決まるので、AI より、アプリか DB（Supabase の定期実行）で作るほうが向いている |

決めること:
- 「準備のタスク」は、AI の判断に任せる部分（何に準備が要るか）があるので、この仕組みが向いている。毎朝のスケジュールタスクにするか、アプリの機能として作るか
- AI が入れたタスクと分かるように、タグ（例: `AI`）を付けるか

## 気をつけること（どの案でも）

- AI はまちがえる。書き込みは、今の MCP と同じく `apply_op` を通す（履歴が残り、戻せる。`docs/db/RESTORE.md`）
- スケジュールタスクが動くたびに、Claude のプランの使用量を使う。頻度を上げすぎない
- スケジュールタスクの設定（プロンプト）は Claude 側にあり、このリポジトリには残らない。作ったら、プロンプトをこのメモか `DECISIONS.md` に写しておく
